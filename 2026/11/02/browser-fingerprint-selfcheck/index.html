当你在登录网站时，网站也在登录你——网络指纹自查

发表于2026-11-02|更新于2026-11-08|社会工程
|浏览量:

你打开一个登录页，还没输入账号，网站已经读完了一轮信息：

你在哪个城市、用哪家运营商、走没走代理；你的系统、浏览器版本、屏幕分辨率、时区、语言；你的显卡、字体、Canvas 渲染结果、音频特征；甚至你的电池状态和 CPU 线程数。

这些信息不需要你点“同意”，也不会弹授权框。它们在你打开页面的那一刻就发生了。

这篇讲五件事：网站到底能看到什么、怎么用现成工具自查、攻击者会怎么把这些数据拼成话术、一次可复刻的授权演练，以及哪些“隐身”其实是错觉。

一、你登录之前，网站已经读完了你

一个典型的中文自检站（who.1ms.dog）会在一次访问里读取 80 多项信息，大致分五层：

层级 网站能读到什么
服务器侧 IP、IPv6、ASN/运营商、DNS 服务器、反向解析、TLS 版本与加密套件、TLS 指纹、数据中心与延迟
请求头 User-Agent、Accept-Language、Client Hints、压缩方式、DNT、Referer
语言与地区 浏览器语言、区域设置、系统时区、时钟格式、一周起始日、键盘布局
指纹 Canvas、WebGL、音频、数学函数、Emoji 版本、字体列表、综合哈希
设备 操作系统、浏览器、CPU 架构与线程数、内存、屏幕、刷新率、显卡、电池、摄像头/麦克风数量、网络类型

页面还会给一个“综合指纹 ID”，并提示你：换网站、开无痕、开 VPN，它都可能不变。

这就是浏览器指纹（browser fingerprinting）的核心：不靠 Cookie，靠一组稳定特征的组合来认人。

二、为什么这件事值得自查

1. 清 Cookie 不等于隐身

Cookie 是网站存在你浏览器里的小纸条，清掉就没了。指纹不是纸条，是从你的设备和浏览器现场算出来的。只要特征组合足够独特，网站换一种方式仍然能把你认出来。

2. 它会被用于精准社工

知道你的系统、浏览器、地区、语言、常用时区，钓鱼邮件和电话就能写得更像真的：

  • “您的 Windows 设备需要更新”——而你确实用 Windows；
  • “您在华东地区的登录异常”——而你确实在那个时区；
  • “请用 Chrome 打开这个页面”——而你确实是 Chrome。

单条信息不敏感，组合起来会显著提高话术的可信度。

3. 它也是风控和反欺诈的工具

需要说清楚：指纹识别本身不是坏事。银行、支付、电商用它识别同一设备上的多账号、异常登录、自动化脚本。对普通用户来说，它也在挡掉一部分盗号与刷单。

问题不在于“被识别”，而在于你不知道自己被识别了多少、被谁识别、用来做什么。

4. 它暴露的不只是隐私，还有攻击面

  • 浏览器版本、插件列表：攻击者可据此选择已知漏洞；
  • 内网 IP、WebRTC 地址：可能暴露真实网络位置；
  • 时区与语言：可用于判断是否在使用代理，或用于地理定位。

四、怎么用：按目的分四条路线

路线 A：5 分钟综合体检

第 1 步：1ms.dog
打开 who.1ms.dog/zh-cn/，从上往下读：

  1. 先看“网站眼里的你”那段结论：地区、系统、浏览器、是否代理。
  2. 再看“全部探测项”：重点看 IP、ASN、DNS、TLS、时区是否与你的实际位置一致。
  3. 记下“综合指纹 ID”。
  4. 开一个无痕窗口再访问一次，比较指纹 ID 是否变化。
  5. 如果用了 VPN，再开 VPN 访问一次，观察哪些值变了、哪些没变。

第 2 步：BrowserLeaks
打开 browserleaks.com，依次看：

  • /ip：IP、ASN、反向解析、时区；
  • /webrtc：是否泄露本地/真实 IP；
  • /dns：DNS 请求走了谁；
  • /canvas、/webgl、/fonts：指纹相关项。

它不给“安全/不安全”的结论，只给原始值，适合逐项确认。

第 3 步：Cover Your Tracks
打开 coveryourtracks.eff.org，运行测试，读两部分：

  • 追踪器拦截：广告跟踪器、隐形跟踪器是否被挡；
  • 指纹唯一性：你的浏览器在访客库里是否独特。

路线 B：看“我有多独特”

AmIUnique
打开 amiunique.org，点击查看自己的指纹，重点看每一项在访客中的占比。占比越低，说明越少见。注意：它会把指纹存入研究数据库，页面上会有说明。

CreepJS
打开 abrahamjuliot.github.io/creepjs/，等它跑完，重点看：

  • FP ID 是否稳定；
  • 各分项是否出现“lies”或异常；
  • 无痕窗口与普通窗口的结果是否一致。

CreepJS 不给你“好/坏”，它更关心浏览器返回值是否自洽。

Pixelscan
打开 pixelscan.net，看它给的结论：一致、存疑、不一致。它偏“风控视角”，适合理解网站如何判断“这个浏览器是否像真人、是否被伪装”。

路线 C：检查 VPN / 代理是否泄露

  1. ipleak.net：看 IP、WebRTC、DNS 三块。如果连了 VPN 却看到本地运营商 IP 或本地 DNS，就是泄露。
  2. DNSLeakTest：专测 DNS，选择标准测试，看解析服务器归属。
  3. BrowserLeaks /webrtc：单独确认 WebRTC 是否绕过代理暴露真实地址。

路线 D：查网络身份与 TLS

  1. ipinfo.io 或 ip.sb：看 IP、ASN、运营商、城市。
  2. bgp.he.net：输入 IP 或 ASN，看前缀与路由关系。
  3. tls.peet.ws/api/all：看 JA3/JA4、TLS 扩展、加密套件。它偏技术，适合排查“为什么换了 IP 仍被识别为同一客户端”。

五、读懂结果：五个常见误判

1. “我的指纹独一无二，说明我被跟踪了”

不一定。指纹独特只说明“可识别性高”，是否被跟踪取决于网站是否使用、是否存储、是否跨站关联。很多风控系统本来就需要识别设备。

2. “开无痕就安全了”

无痕只清理本地 Cookie、缓存与历史，不改变 Canvas、字体、屏幕、时区这些特征。指纹 ID 很可能不变。

3. “挂了 VPN 就隐身了”

VPN 改变的是出口 IP 与部分网络路径，不改变浏览器指纹。很多站点会同时看 IP 与时区、语言是否匹配；IP 在海外、时区在国内，本身就是异常信号。

4. “扩展装得越多越安全”

扩展会改变浏览器行为，也可能增加指纹独特性。一个少见的扩展组合，反而更容易被认出来。

5. “不同网站的分数可以比较”

不能。每个站的访客库、算法、判定标准都不同。A 站 70 分、B 站 30 分，不说明你“变安全了”或“变危险了”。

六、反面教学：攻击者会怎么读这些数据

把前面那些“网站能看到什么”换成攻击者视角，会发现它们不是一堆参数，而是一条从设备到话术的流水线。

1. 攻击者的阅读顺序

  1. 先分人和机器：IP 是机房还是住宅？ASN 是云厂商还是运营商？时区与 IP 所在地是否一致？——判断目标是否在用 VPN、代理，或是否值得继续。
  2. 再看设备：UA 与 Client Hints 指向 Windows 还是 macOS、桌面还是手机；屏幕、字体、Canvas 是否像真实用户，还是像自动化环境。
  3. 再看习惯：公开帖子的发布时间、语言、地理位置、常用平台；这些决定“什么时候联系最自然”。
  4. 最后才设计话术：IT、供应商、HR、银行、快递——选一个与设备、时间、身份都匹配的角色。

注意顺序：先确认环境，再设计故事。 反过来，故事很容易露馅。

2. 工具映射：每个阶段看什么、怎么断

阶段 常见工具 攻击者想确认什么 防御动作
网络定位 ipinfo.io、bgp.he.net、1ms.dog 出口地区、ASN、住宅/机房、是否代理 出口 IP 与系统时区保持一致；不滥用免费代理
泄露排查 ipleak.net、BrowserLeaks /webrtc、/dns WebRTC/DNS 是否暴露真实地址 限制 WebRTC；使用加密 DNS；连 VPN 后复查
客户端识别 1ms.dog、BrowserLeaks、CreepJS 系统、浏览器、字体、Canvas 是否自洽 用常见浏览器与默认配置；少装扩展
唯一性判断 AmIUnique、Pixelscan 指纹是否独特、是否像伪装 分身份、分浏览器；不靠反检测工具“改指纹”
邮件头分析 邮件原始头（Received、Message-ID、时区） 发件服务器、客户端、时区 不公开原始邮件；对外用企业邮箱
账号关联 WhatsMyName、Maigret 同一昵称还出现在哪些平台 不同平台不同昵称；公开与私密身份分离
泄露记录 Have I Been Pwned 邮箱是否出现在泄露库 改密码、开两步验证、不复用
企业信息 工商信息、招聘 JD、官网 组织结构、技术栈、供应商 信息分级；官网与 JD 少暴露内部细节

3. 一条虚构的攻击链

假设目标是某公司的采购专员，攻击者只做公开信息收集：

  1. 公司官网的“联系我们”列出采购部公共邮箱与座机。
  2. 招聘 JD 提到“使用某办公套件与 ERP”，暗示技术栈。
  3. 目标在公开社区发过一张截图，界面是 Windows 上的某邮件客户端，发布时间是工作日上午。
  4. 公开资料能查到姓名与职务，但没有手机号。

到这里，攻击者已经可以设计一个很像真的开场：

“我是 IT 服务台的，看到你这边邮件客户端同步异常，需要你配合点一下设置。”

这句话之所以可信，不是因为攻击者技术高，而是因为设备、软件、时间、职务四个点都对上了。

这条链在哪一步会断？

  • 截图里不出现完整界面、时间、用户名；
  • 对外联系只用公共邮箱，不公开个人邮箱；
  • 接到“IT”电话，挂断后用内部通讯录回拨；
  • 邮件客户端出问题，只从官方入口进，不点对方给的链接；
  • 任何“验证身份”的请求，都走第二渠道确认。

4. 企业做授权演练时，边界在哪

如果要把这套视角用于自查或红队演练，至少写清四件事：

  1. 书面授权：范围、目标、时间窗口、允许使用的手段。
  2. 只用公开信息与测试账号：不碰员工个人账号，不获取凭据。
  3. 不做真实伤害：不投递恶意附件，不诱导转账，不冒用执法身份。
  4. 记录与脱敏：过程留日志，报告隐去个人信息，发现真实风险立即停止并通知。

七、桌面推演：一次授权的 Help Desk 演练

1. 场景设定

  • 目标：某科技公司（下称 A 公司），约 200 人，IT 服务台外包。
  • 测试目标：员工在“强制启用 passkey / 更新 MFA”话术下，是否会按来电者指示操作。
  • 授权前提：书面范围、时间窗口、测试域名、禁用手段、数据留存方式、报告对象。

2. 七步推演

步骤 攻击者会怎么想 教学中的安全复刻 防御断点
0. 授权 先确认哪些能做、哪些不能碰 签范围书：部门、时间、禁用手段 无授权不演练
1. 公开信息 官网、招聘 JD、公开资料能拼出什么 只收集公开页面，记录来源与时间 官网少放内部系统名；JD 不暴露技术栈
2. 选目标 谁最容易配合？新员工、财务、前台？ 选一名同意参与的测试员工 新员工入职先培训
3. 设计 pretext 什么理由与他的设备、时间、岗位匹配？ 用“IT 服务台 + 安全升级”模板，只写结构，不写真实凭据 员工知道“IT 不会索要验证码”
4. 投递 邮件怎么显得像内部？ 演练专用域名 + 教育页，只记录点击，不收集任何输入 外部发件人标识、邮件过滤
5. 电话跟进 如何用第二个渠道增加可信度？ 用演练号码；按合规要求明确告知这是测试 挂断后用通讯录回拨
6. 度量 点击率、报告率、是否回拨 只统计点击/报告/回拨，不记录密码 报告通道是否足够容易
7. 复盘 哪一步最容易被骗？ 脱敏报告，按流程/培训/技术归因 修补流程，不惩罚个人

3. 关键话术：只给结构，不给全文

这类电话之所以有效，不是话术多精巧，而是它同时满足了三个条件：

  1. 身份匹配：对方知道你的岗位、在用的系统、大概的作息。
  2. 理由合理：安全升级、MFA 迁移、账号异常，都是日常会发生的事。
  3. 动作很小：只是“点一下”“读一个码”“装个工具”，看起来不严重。

教学里只保留这个结构：

“我是 IT 服务台的，看到你这边……需要你配合……大概几分钟。”

不写完整脚本，是因为一旦写成可照读的全文，它就会从教学材料变成可复用的话术模板。

4. 这条链在哪一步会断

  • 回拨：挂断，用公司通讯录里的号码打回去，不用来电显示上的号码。
  • 不按指示操作：不打开对方给的链接，不安装远程工具，不读验证码。
  • 第二渠道：涉及账号、转账、权限，必须用另一个渠道确认。
  • 报告：把可疑来电/邮件转给指定邮箱，而不是删掉了事。
  • 培训：让员工知道“拒绝”不会给自己惹麻烦。

八、降低暴露：先定威胁模型

“隐私”不是一个开关。先问自己：你要防的是谁？

  • 广告商跨站跟踪？
  • 陌生人的社工与钓鱼？
  • 公司/学校的内网管理？
  • 还是高风险环境下的定向攻击？

不同目标，做法不同。

普通用户：做减法和分层

  1. 浏览器保持更新：版本漏洞比指纹更现实。
  2. 少装扩展：只留必要的，定期清理。
  3. 分开身份：工作、购物、社交用不同浏览器或不同配置文件，避免一个指纹串起所有账号。
  4. 敏感操作固定环境：网银、邮箱只在固定浏览器里登录，不随便点邮件链接。
  5. 检查 WebRTC 与 DNS：用 ipleak、DNSLeakTest 确认没有泄露。
  6. 不要用真实信息做昵称：减少指纹之外的关联线索。

高敏感场景：接受取舍

  • 使用带反指纹保护的浏览器（如 Firefox 的 resistFingerprinting、Brave、Safari 的防跟踪），但要知道它们也可能让某些网站功能异常。
  • 用 VPN 改变出口 IP，同时保证时区、语言、DNS 与出口地区尽量一致，避免“IP 在海外、系统在国内”的矛盾。
  • 需要强匿名时，Tor Browser 是更彻底的方案，但速度与可用性会明显下降。
  • 虚拟机和隔离环境可以进一步分离身份，但维护成本高。

企业：把指纹当成资产暴露面

  • 盘点官网、登录页、帮助中心会收集哪些信息；
  • 不在前端暴露内部系统名、版本号、调试信息；
  • 对员工做钓鱼与社工培训，而不是只讲“别点链接”；
  • 把设备指纹用于风控时，明确告知与合规边界。

不建议使用“反检测浏览器”去绕过平台风控、批量注册或伪装身份。那是规避规则，不是隐私保护。

九、结语

“网站眼里的你”不是一张照片，而是一组稳定的特征：IP 会变，Cookie 会清，但屏幕、字体、时区、渲染结果往往不动。

理解指纹，不是为了从此消失——那既不现实，也会让正常服务变得更难用。更实际的目标是：

知道自己暴露了什么，减少不必要的独特性，把敏感身份隔离开。

你不需要成为网络上的隐形人，只需要让“认出你”这件事变得不那么容易、不那么划算。

附：网络指纹自查清单

  1. 打开 who.1ms.dog/zh-cn/，完整读一遍探测项。
  2. 记下综合指纹 ID，开无痕窗口再访问，比较是否变化。
  3. 用 BrowserLeaks 检查 /webrtc、/dns 是否泄露。
  4. 用 Cover Your Tracks 看追踪器拦截与指纹唯一性。
  5. 用 AmIUnique 看自己的指纹稀有度。
  6. 用 CreepJS 检查浏览器返回值是否自洽。
  7. 连 VPN 后用 ipleak 与 DNSLeakTest 复查 IP/DNS。
  8. 用 ipinfo.io 与 bgp.he.net 确认 ASN 与出口位置。
  9. 清理不用的浏览器扩展，减少独特性。
  10. 工作、购物、社交分浏览器或分配置文件。
  11. 网银、邮箱只在固定环境登录，不点邮件里的链接。
  12. 每季度复查一次，浏览器大版本更新后也复查。
