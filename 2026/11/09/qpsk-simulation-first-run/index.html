记第一次跑 QPSK 仿真

发表于2026-11-09|更新于2026-11-09|技术博客
|浏览量:

接到这个任务的时候，我对 QPSK 的全部认识只有四个字母。

目标听起来不复杂：写一个脚本，跑出一条误码率曲线，再和教科书上的理论线对上。我以为难点在代码，真正跑完才发现，代码是最不难的部分。难的是搞清楚每个数字的单位，以及判断一条曲线什么时候不可信。

这篇记录第一次跑 QPSK 仿真的过程：链路怎么拆、最容易卡住的换算在哪、10 dB 处那 1 dB 的偏差是怎么来的，以及最后我敢说和不敢说的分别是什么。

一、先画链路，再写代码

零基础最容易犯的错，是打开编辑器就写 import numpy。这次我强迫自己先做一件事：把链路拆成六段，每一段用一句人话写清楚。

比特生成 → Gray 映射 → QPSK 调制 → AWGN 信道 → 相干解调 → 误码统计

拆完才发现，所谓“仿真”，就是把这条链在电脑里走一遍，走很多很多遍，然后数错。

这里有个容易忽略的点：真实系统里，误码率很少能像教科书那样直接算出来。一旦加了成形滤波、同步误差或者编码，闭式公式就写不出来了。蒙特卡洛的做法很笨，但通用——把链路跑足够多次，用错误数除以总比特数，去逼近那个概率。

几个第一次接触时最容易糊的词：

  • 比特：0 或 1。
  • 符号：一次调制发出去的东西。QPSK 一个符号带 2 个比特，所以同样发 10 亿比特，QPSK 只需要 5 亿个符号。
  • I / Q：两路正交的基带分量，可以理解成平面上的横坐标和纵坐标。一个 QPSK 符号就是平面上的一个点。
  • AWGN：加性高斯白噪声。说人话就是，信号在信道里走一趟，每个维度都被加上一点随机的、服从正态分布的扰动。

Gray 映射的作用，是让相邻星座点只差一个比特。00 映射到 (-1,-1)，01 到 (-1,+1)，10 到 (+1,-1)，11 到 (+1,+1)。接收端只需要看实部正负判第一位、虚部正负判第二位。一个符号判错，通常只错一位——这就是 Gray 映射在误码率上的价值。

调制时还要除以 √2，把符号能量归一化成 1。这个细节当时没觉得重要，后面算噪声方差时全靠它。

二、第一个卡点：Eb/N0 不是 SNR

链路画完，真正让人停下来的是噪声。

教科书横轴写的是 Eb/N0，单位 dB。代码里要的是噪声标准差 σ。这两个东西之间隔着一串换算，最容易混的是“每个符号”和“每个比特”。

正确的推导是这样：

  1. 先把 dB 换成线性值：γ = 10^(Eb/N0 ÷ 10)。
  2. 符号能量归一化后 Es = 1；QPSK 每个符号带 2 比特，所以 Es = 2Eb。
  3. 噪声单边功率谱密度 N0 = Eb/γ = Es/(2γ) = 1/(2γ)。
  4. 每个实维度的噪声方差是 N0/2，所以标准差 σ = √(N0/2) = 1/(2√γ)。

落到代码里就是 sigma = 1.0 / (2.0 * math.sqrt(gamma))。

第一次看到 1/(2√γ) 这种式子会觉得绕。可以反过来检查：γ 每翻一倍，σ 应该缩小到原来的 1/√2，也就是噪声功率减半。用这个关系去验算，比死记公式可靠。

为什么横轴不用 SNR？因为 SNR 跟带宽绑定；Eb/N0 是每比特能量比噪声功率谱密度，去掉了带宽和调制方式的影响，不同系统之间可以直接比。QPSK 里 Es = 2Eb，所以 Es/N0 比 Eb/N0 大 3 dB。

还有一个容易漏的点：复基带噪声要在 I、Q 两个实维度上各加一次独立的高斯噪声，也就是 σ × (randn + 1j × randn)。只给实部加，或者两个维度共用同一个随机数，图可能“看起来还行”，但那是错的。

这一步推错，后面所有结果都没有意义。所以每次改噪声相关的东西，最好先把公式在纸上重推一遍，再动代码。

三、第一次跑通，曲线漂亮得让人心虚

第一版参数：11 个信噪比点，0 到 10 dB，步长 1 dB；每个点 2×10⁷ 比特；随机种子固定为 20261108。

跑完第一眼是高兴的。0 到 8 dB，仿真点和理论线几乎完全重合。但拉到 10 dB，最后一个点明显翘了上去：

  • 理论值 3.87×10⁻⁶
  • 仿真值 4.95×10⁻⁶
  • 换算成 dB，偏了 1.07 dB

第一反应是归一化写错了，或者判决门限有问题。把噪声方差的推导、Gray 映射、判决条件全部重推了一遍，都没错。

然后去数了一个数：那个点上，仿真一共统计到 99 个错误。

问题不在模型，在样本量。

这里最关键的一步，不是改代码，而是先把错误数打出来。错误数一出来，问题就从“模型对不对”变成了“样本够不够”，方向立刻就变了。

蒙特卡洛仿真的统计涨落大约按 1/√N 走，N 是错误数。99 个错误，相对误差本来就在 10% 量级，偶尔抖到 20%–30% 并不奇怪；而 BER 差 28%，换算到 dB 就是 1.07 dB。看到的不是“模型偏了”，是“样本不够”。

改法很直接：每个点从 2×10⁷ 比特提到 5×10⁷ 比特。10 dB 处的错误数从 99 变成 185，偏差从 1.07 dB 降到 0.197 dB。

这件事让我记住了一条比代码更重要的经验：

仿真精度由错误数决定，不由比特数决定。经验上每个信噪比点至少要统计到 100 个错误；想让高信噪比点更稳，还得更多。

顺带一个工程细节：5×10⁷ 比特如果一次性生成，内存会很难看。脚本按每段 2×10⁶ 个符号分段累加，跑完一段释放一段，峰值就压下来了。这也意味着脚本可以长时间跑，不会因为内存被系统杀掉。

四、结果

最终 11 个点的数据如下（每点 5×10⁷ 比特）：

Eb/N0 (dB) 理论 BER 仿真 BER 错误数
0 7.8650e-02 7.8646e-02 3,932,281
1 5.6282e-02 5.6310e-02 2,815,525
2 3.7506e-02 3.7527e-02 1,876,359
3 2.2878e-02 2.2871e-02 1,143,569
4 1.2501e-02 1.2510e-02 625,496
5 5.9539e-03 5.9636e-03 298,180
6 2.3883e-03 2.3930e-03 119,649
7 7.7267e-04 7.7026e-04 38,513
8 1.9091e-04 1.8832e-04 9,416
9 3.3627e-05 3.5000e-05 1,750
10 3.8721e-06 3.7000e-06 185

仿真相对理论曲线，最大偏差 0.197 dB，平均偏差 0.043 dB。0–8 dB 段基本重合，9–10 dB 有轻微抖动，原因还是错误数少。

185 个错误对应约 7% 的相对误差，换算到 dB 差不多就是 0.2 dB。也就是说，这条曲线在高信噪比端的精度上限，是被错误数卡住的，不是被代码卡住的。想把 10 dB 点再压准，只能继续加比特。

理论值用闭式公式算：Gray 编码 QPSK 在 AWGN 下的误比特率是

Pb = Q(√(2Eb/N0)) = 0.5 · erfc(√(Eb/N0))

仿真走蒙特卡洛，理论走公式，两条独立路径互相验证。这比“图看起来像”可靠得多。结果同时写进 CSV 和 Markdown，每一行都能对上错误数；后面换参数，直接拿同一套脚本重跑，不用重新搭链路。

另外画了一张星座图，取 0、5、10 dB 三档，每档 3000 个接收符号：

  • 0 dB：点摊满整个平面，四个团几乎糊在一起；
  • 5 dB：四团开始分开，边缘还在扩散；
  • 10 dB：四团收得很紧，判决几乎不会错。

曲线看的是统计结果，星座图看的是瞬时分布，说的是同一件事。

五、不是所有图都是仿真

这次还画了两张图：链路六段结构图，和一张 ping 报文的分层图。它们不产生数据，只是把结构画清楚，不能算仿真结果。

分层那张图按 RFC 791 / 792 / 802.3 拆了一个 Windows 默认 ping：32 B 应用数据加 8 B ICMP、20 B IPv4、14 B 以太网头，总共 74 B，头部占 42 B，约 57%。这些数字来自协议规定，不是跑出来的。

把“算出来的”和“画出来的”分开，是这次学到的另一件事。写总结时如果混在一起，别人会以为你也仿真了协议栈。

六、这条曲线能证明什么

跑通不等于什么都证明了。我给自己划了边界。

能证明：

  • 链路六段模型搭对了；
  • 噪声方差与 Es = 2Eb 的换算自洽；
  • Gray 映射和理论公式对得上；
  • 蒙特卡洛方法本身可靠，结果可复现。

不能证明：

  • 真实信道下的性能——这里只有 AWGN，没有衰落和多径；
  • 有同步误差时的性能——这里假设载波相位已知；
  • 有成形滤波时的性能——这里没有脉冲成形；
  • 有信道编码时的性能——这里没有编码；
  • 硬件实现后的性能——这里没有定点、量化和射频损伤。

一句话：这是地基，不是房子。

它不指导芯片怎么设计，但它是后续所有对比的基准线。以后加编码、加同步、加衰落，每一项都要相对这条线算增益或损失。

七、我学到的四件事

  1. 先定位，再动手。 曲线偏了，先算错误数，再看模型。第一反应往往是错的。
  2. 理论和仿真要走两条路。 用同一套假设算两遍，对上了也不说明什么；闭式公式和蒙特卡洛对上了，才有一点说服力。
  3. 可复现是底线。 固定随机种子，分段累加，一条命令重跑。别人拿到的数应该和你一样。
  4. 知道自己不知道什么。 不说“优化了算法”，不说“熟练掌握”。被问到没学过的细节，就回去补。

还有一个反面教训：不要为了让曲线好看去平滑数据或者拟合。9–10 dB 的抖动是真实的统计涨落，抹平它等于把误差藏起来。答辩时被问“为什么这个点不在线上”，能答出“因为只有 185 个错误”，比一条漂亮但说不清来路的曲线更有用。

下一步想做的是：加根升余弦成形和匹配滤波，看滚降系数的影响；加频偏和相位噪声，看误码平台出现在哪；再加定时偏差、Rayleigh 衰落、LDPC 或 Polar 编码，最后对比 QPSK / 16QAM / 64QAM。

脚本固定了随机种子 20261108，一条命令重跑，结果一致。主脚本跑完 11 个点大约 1–2 分钟，星座图和结构图几秒。成本很低，低到没有理由不复现。

第一次跑仿真，最大的收获不是那条曲线，而是知道了它什么时候不可信。

（11 个点，每点 5×10⁷ 比特，一共 5.5 亿比特，才换来这一条线。）
