这篇文章记录本站从零到上线的完整过程：技术选型、环境搭建、视觉改造、组件接入，以及踩过的坑。既是归档，也给后来者一份可复用的清单。

一、技术选型

个人博客常见的三条路：

方案 优点 代价
Wix 等 SaaS 拖拽建站，零代码 去广告要付费；数据锁在平台
WordPress 生态庞大，插件齐全 需要服务器，要备案，维护成本高
静态博客（Hexo） 免费、极快、数据自持 需要命令行基础

最终选择 Hexo + Butterfly 主题 + GitHub Pages：零成本、纯静态、内容完全掌握在自己手里。

五、ASCII 加载动画

首次访问时播放一段纯代码实现的加载动画：字符先随机闪烁，再逐个定格，最终拼出 REC0 的 ASCII 图形。

实现要点：

  1. 用 <pre> + 逐字符 <span> 构建网格；
  2. 每个字符有独立的「出现时间」，出现后继续闪烁 0.4 秒，再定格为最终字符；
  3. 背景中心有一层椭圆光晕，随字符出现由暗到亮，模拟灯泡点亮；
  4. 用 localStorage 记录，只在首次访问播放。

六、评论与留言

统一使用 Giscus（基于 GitHub Discussions），无需后端、免费，天然支持点赞、回复与 GitHub 登录。

  • 首页留言板：注入到文章列表下方
  • 文章评论：在主题配置中启用

管理留言只需到仓库的 Discussions → Announcements 中删除对应讨论。

七、悬浮音乐播放器

播放器在 APlayer + MetingJS 基础上做了三件事：

  1. 本地化依赖：把 APlayer、Meting、PJAX 的脚本下载到 source/vendor/，避免 CDN 在境内不稳定；
  2. 可拖动 + 位置记忆：外层包裹层使用 transform 移动，位置存 localStorage；
  3. 收进设置面板：默认关闭，点右下角齿轮 → 🎵 才创建播放器（不请求歌单、不加载音频）。

为了「切页不断播」，开启了 PJAX，并把右栏导航、留言板、图廊三个脚本都改为同时监听 pjax:complete。

八、踩坑记录

这是最有价值的部分。

1. YAML 缩进与重复键

一行只能有一个键名。看到 bad indentation of a mapping entry，照着报错行号改。

2. APlayer 控制栏不显示

组件模板里信息区默认是 display: none，只有 mini 为真时才会被取消隐藏。若不注意，会看到「只有封面、没有按钮」的空白卡片。

3. 圆角裁掉了控件

给 .aplayer-body 加 overflow: hidden 会把溢出在 66px 之外的控制条裁掉。

4. 暗色主题下图标「隐形」

APlayer 的播放/音量图标默认是黑色 SVG（配白底设计的），在深色卡片上等于看不见，必须覆盖 fill。

5. 零文章时首页不生成

Hexo 在没有任何文章时不会生成 index.html，根路径直接 404。所以站点至少要保留一篇正式文章。

6. CDN 依赖的脆弱性

api.i-meto.com 已失效、jsDelivr 在境内不稳定。对策是：能本地化的静态资源就本地化，第三方 API 要做可替换设计。

十、版本管理

源码使用 Git 管理，并打上 v1 标签作为首个稳定版本。以后每次较大的改动，都可以打一个新标签（v2、v3……），方便回溯与回滚。

小结

从空白目录到一个可用、有辨识度的个人站点，核心其实只有三件事：

  1. 选对技术栈——静态博客适合长期写作者；
  2. 把配置和自定义分离——_config.butterfly.yml + custom.css + js/，升级不丢改动；
  3. 越少依赖越好——能本地化的就本地化，能自己实现的就不装插件。
